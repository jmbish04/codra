# Webhook auth fix, delivery transparency, and open-PR sync

Date: 2026-07-24
Status: Approved (design)

## Problem

GitHub webhook deliveries to codra are failing, so pull requests stop being
picked up for review. Example: `core-remodel` has open PRs up to #210, but the
last PR codra logged a job for is #202.

Two root problems:

1. **Broken signature verification.** `handleGitHubWebhook`
   ([webhook.ts:24](../../../src/server/routes/webhook.ts)) verifies the
   HMAC signature against `getSecret(c.env, 'GITHUB_WEBHOOK_SECRET')` — a plain
   env var. The intended source is the Secrets Store binding `WORKER_API_KEY`
   (`await env.WORKER_API_KEY.get()`). When `GITHUB_WEBHOOK_SECRET` is unset,
   `getSecret` throws → 500; when stale, verify returns false → 401. Every
   delivery fails.

2. **No recovery and no visibility.** Review jobs are created *only* from live
   webhook deliveries. The one cron job (`0 */6 * * *`) runs the knowledge-base
   sync — it does not reconcile open PRs. So any PR whose delivery was missed
   during the outage is lost forever. And `recordWebhookDelivery` runs *after*
   signature verification, so rejected/failed deliveries are never recorded —
   there is no way to see what failed.

## Goals

- Fix webhook verification to use `WORKER_API_KEY` (drop `GITHUB_WEBHOOK_SECRET`).
- Record **every** delivery with a definite outcome, including rejected/errored.
- A dashboard page showing every delivery, its outcome, and the codra action it
  triggered (with a detail drawer).
- A "Sync open PRs" action to enqueue review jobs for open PRs that have no job
  (recovers the already-missed PRs and any future gap).

## Non-goals

- No per-delivery "reprocess" button (deferred; the sync action covers recovery).
- No change to the review pipeline itself.

## Part 1 — Fix webhook auth

In `handleGitHubWebhook`, replace:

```ts
const webhookSecret = getSecret(c.env, 'GITHUB_WEBHOOK_SECRET');
```

with the Secrets Store value:

```ts
const webhookSecret = await getWorkerApiKey(c.env); // WORKER_API_KEY.get()
```

`getWorkerApiKey` already exists in `utils/secrets.ts`. GitHub's webhook secret
must be configured to the same value as `WORKER_API_KEY`. Stop reading
`GITHUB_WEBHOOK_SECRET` anywhere; leave the generated type in
`worker-env.d.ts` alone (regenerated by `wrangler types`), but remove the
`.dev.vars`/wrangler var if present so it can't drift back into use.

## Part 2 — Record every delivery + outcome

### Schema

Add columns to `webhook_deliveries`
(`src/server/db/schemas/webhooks/…`):

| column      | type              | notes                                        |
|-------------|-------------------|----------------------------------------------|
| `outcome`   | text NOT NULL     | default `'received'`; finalized per exit     |
| `action`    | text (nullable)   | codra action, e.g. `review`, `kb_update`     |
| `pr_number` | integer (nullable)| PR the delivery concerns                     |
| `job_id`    | text (nullable)   | review job created, if any                   |
| `error`     | text (nullable)   | error message when `outcome = 'error'`       |

Migration via `pnpm run db:generate` (drizzle-kit). Existing rows backfill to
`outcome = 'legacy'`.

### Outcome taxonomy (finite)

| outcome                     | meaning                                                        | action        |
|-----------------------------|----------------------------------------------------------------|---------------|
| `rejected_signature`        | missing/invalid HMAC signature (401)                           | –             |
| `invalid_payload`           | missing headers or unparseable JSON (400)                      | –             |
| `duplicate`                 | `delivery_id` already recorded                                 | –             |
| `ignored_unsupported_event` | event not in supported set                                     | –             |
| `ignored_no_repository`     | payload has no repository                                      | –             |
| `ignored_no_installation`   | no installation id                                             | –             |
| `ignored_repo_disabled`     | repo config `enabled = false`                                  | –             |
| `kb_updated`                | star/watch/fork updated knowledge base                         | `kb_update`   |
| `job_created`               | review job inserted                                            | `review`      |
| `queued`                    | sent to `REVIEW_QUEUE` for deferred handling (close/mention)   | `queued`      |
| `no_action`                 | valid + supported but produced no job (e.g. wrong branch)      | –             |
| `error`                     | exception during processing (500)                              | –             |

### Recording flow

Record the delivery **before** signature verification, as soon as
`deliveryId` + `eventName` are known. Recording must never break webhook
processing — wrap DB writes in try/catch and log on failure.

To avoid scattering updates across the handler's many early returns, introduce a
single local helper in the route:

```ts
const finish = async (
  status: number,
  body: unknown,
  outcome: DeliveryOutcome,
  extra?: { action?: string; prNumber?: number; jobId?: string; error?: string },
) => {
  await finalizeWebhookDelivery(c.env, deliveryId, { outcome, ...extra }).catch(() => {});
  return c.json(body, status);
};
```

Every `return` in the handler becomes a `return finish(...)`. If missing
headers prevent knowing `deliveryId`, skip recording and return 400 directly
(nothing to dedup on). The whole body is wrapped so an unexpected throw
finalizes `outcome = 'error'` and returns 500 (GitHub retries transient 5xx).

`recordWebhookDelivery` inserts the initial row (payload as-received, dedup via
`delivery_id` unique + `onConflictDoNothing`) and returns whether it was new.
A duplicate short-circuits to `finish(202, …, 'duplicate')`.

## Part 3 — Sync open PRs

### GitHub client

Add `listOpenPullRequests(owner, repo)` to `GitHubClient` — paginated
`GET /repos/{owner}/{repo}/pulls?state=open&per_page=100`. Returns number,
title, user.login, head.sha, head.ref, base.sha, base.ref.

### Endpoint

`POST /api/webhooks/sync` (dashboard-authed). Optional `?repo=owner/name` to
scope to one repo; default is all enabled repos.

Source of repos: join `repo_configs` (`enabled = true`) with `repositories`
(`installation_id`, `owner`, `repo`).

For each repo, for each open PR:

1. `findExistingJobForHead({ owner, repo, prNumber, commitSha: head.sha, trigger: 'sync' })`.
   If a job already exists for that head → skip.
2. Else `loadRepoConfig` → if disabled, skip. Otherwise `insertJob({ …, trigger: 'sync', commitSha: head.sha, baseSha: base.sha })`, then `supersedeOlderJobs`, then dispatch to the `RepoAgent` DO exactly as the webhook path does.

Add `'sync'` to the `insertJob` trigger union (`'auto' | 'mention' | 'retry' | 'sync'`).

Returns a summary: `{ repos: [{ owner, repo, openPrs, enqueued, skipped }], totalEnqueued }`.

Dedup guarantees the action is idempotent — re-running enqueues nothing new.

## Part 4 — API + frontend

### API

- `GET /api/webhooks` — filters `outcome`, `event`, `repo`, plus `limit`/`offset`.
  Returns rows: `id`, `received_at`, `event_name`, `owner`, `repo`, `outcome`,
  `action`, `pr_number`, `job_id`, `error`.
- `GET /api/webhooks/:id` — full row including parsed `payload`.
- `POST /api/webhooks/sync` — as above.

New router `src/server/routes/api/webhooks.ts`, registered under `/api/webhooks`
(behind existing `requireSession` + `requireCsrfHeader`).

### Frontend

New page `src/client/pages/webhooks.tsx`:

- Header with a **Sync open PRs** button (calls `POST /api/webhooks/sync`,
  toasts the summary).
- Filter chips: outcome, event, repo.
- Table: time, event, repo, outcome badge (color-coded by class:
  green = job_created/kb_updated/queued, gray = ignored\_\*/no_action,
  red = rejected/invalid/error), PR (link to job when `job_id` present).
- Row click → drawer: full payload JSON, outcome + reason, linked job.

Wire route `webhooks` into `main.tsx` under `AppShell`, and add a nav link in
`components/layout/app-shell.tsx` next to Jobs.

## Data flow

```
GitHub → POST /webhook
  → record delivery (outcome 'received')
  → verify HMAC against WORKER_API_KEY
      fail → finish(401, 'rejected_signature')
  → parse/dedup → route by event
      → finish(…, job_created | kb_updated | queued | no_action | ignored_* )
  (throw anywhere → finish(500, 'error'))

Dashboard → GET /api/webhooks       (table)
Dashboard → GET /api/webhooks/:id   (drawer)
Dashboard → POST /api/webhooks/sync (recover missed PRs)
```

## Error handling

- Delivery record/finalize failures are swallowed (logged), never block the
  response to GitHub.
- Signature rejects return 401 (GitHub marks the delivery failed — intended).
- Genuine processing exceptions return 500 so GitHub retries transient errors;
  the delivery row is finalized `outcome = 'error'` with the message.
- Sync endpoint: a per-PR failure is collected into the summary, not fatal to
  the whole run.

## Testing

- `verifyGitHubWebhookSignature` verifies a signature generated with the
  `WORKER_API_KEY` value (unit).
- Webhook handler finalizes the correct outcome for each branch: rejected,
  duplicate, ignored, job_created, no_action (integration, mocked env).
- Sync: given open PRs where some already have a job for the current head,
  only the missing ones are enqueued; a second run enqueues nothing
  (idempotence) — one assert-based test.
- Migration applies cleanly (`migrate:local`).

## Migration / rollout

1. Ship code + migration.
2. Set GitHub App webhook secret = `WORKER_API_KEY` value.
3. Deploy; confirm new deliveries record `job_created`.
4. Run **Sync open PRs** to recover #203–#210 and anything else missed.
